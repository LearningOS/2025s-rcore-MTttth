## 功能总结
### 重写了系统调用 ```sys_trace```，支持以下三类操作：

1. 读取操作（trace_request = 0）：从当前任务的 id 地址处读取一个字节的无符号整数。先是将用户虚拟地址映射到物理内存空间，最后在物理内存进行数据读取。
2. 写入操作（trace_request = 1）：将 data 的最低字节写入当前任务的 id 地址处。先是将用户虚拟地址映射到物理内存空间，最后在物理地址完成数据写入。
3. 查询调用次数（trace_request = 2）：返回当前任务对系统调用编号为 id 的累计调用次数（包含本次查询）。与 ```lab1``` 基本没有变动。

### 缺页

#### 缺页导致的异常
1. ```Instruction Page Fault``` 
   执行指令时页未映射或不可执行
2. ```Load Page Fault```
   加载数据（读内存）时页未映射或不可读
3. ```Store/AMO Page Fault```
   存储数据（写内存）时页未映射或不可写

#### 发生缺页时相关重要寄存器的值
| 寄存器名 | 含义                   | 用途                                       |
| -------- | ---------------------- | ------------------------------------------ |
| sepc     | 保存引发异常的指令地址 | 用于异常返回时恢复指令执行                 |
| stval    | 存储导致异常的虚拟地址 | 缺页时为访问的虚地址                       |
| scause   | 指示异常原因           | 判断是 page fault 还是其他异常             |
| sstatus  | 包含当前 CPU 状态      | 可用于检查特权级等信息                     |
| satp     | 保存页表根地址         | 用于定位根页表的 PPN                       |
| sp/tp/gp | 等	通用寄存器          | 有时可用来判断是否是用户栈或全局数据区缺页 |

#### Lazy 策略的好处
1. 节省内存资源
   如果程序的一部分代码或数据从未被访问，那么这些页面就永远不会分配物理页，避免了浪费内存。例如 ```.text``` 段中某些函数永远不会调用，不需要为其分配物理页。
2. 加快程序启动速度
   启动进程时，OS 无需马上加载整个可执行文件的所有段（如 ```.text```, ```.data```, ```.bss```），只需设置页表中的占位信息，等待实际访问时再加载，从而让程序更快启动。
3. 支持按需加载和共享内存机制
   类似 ```.text``` 段可以多个进程共享一个物理页，只有在写入时再复制（写时复制，COW）。
4. 方便实现更高级的内存管理功能
   如匿名映射（mmap）、文件映射（memory-mapped file）、需求分页（demand paging）。

#### Lazy 映射与页表空间估算（SV39 架构）

##### 10GB 虚拟内存对应的页表空间估算
- 三级页表：`VPN[2]` → `VPN[1]` → `VPN[0]`
- 每级页表大小：512 项 × 8 字节 = 4KB
- 页面大小：4KB

##### 映射 10GB 所需页面数
10GB / 4KB = 2,621,440 页 ≈ 2.5M 页

- 每个页表项映射 1 个页
- 底层页表（L0）：需要 2.5M / 512 = **5120 个 L0 页表**
- 中间页表（L1）：5120 / 512 = **10 个 L1 页表**
- 顶层页表（L2）：只需 **1 个 L2 页表**

##### 总页表内存开销
L0: 5120 页 × 4KB = 20MB  
L1: 10 页 × 4KB = 40KB  
L2: 1 页 × 4KB = 4KB  
总计 ≈ 20MB

#### Lazy 策略下的处理缺页异常
- 操作系统会检查访问的虚拟地址是否在合法的地址空间范围内。如果访问的是合法的内存区域（即属于进程申请的内存空间），则进行内存分配和映射。
- 系统会分配一个物理页面，并为该虚拟地址更新页表项（PTE），标记该页为有效，并设置适当的权限位（如读/写权限）。
- 内核将物理页面与虚拟地址建立映射关系。此时，虚拟地址的页表项就指向了物理地址。
- 更新页表后，操作系统需要刷新 TLB（快速缓存），确保接下来访问该虚拟地址时能够正确映射到物理内存。
- 在页表更新完毕后，用户程序可以继续访问该内存页面，并且操作系统不会再触发缺页异常，直到用户访问一个尚未分配的虚拟地址。
- 如果用户访问的地址超出了合法的虚拟地址空间，操作系统应当触发相应的异常，通常会导致进程崩溃或返回错误码（如 SIGSEGV）。
  
#### swap 策略下的页表项(PTE)
当页面由于 swap 策略被换出到磁盘时，它的物理页面被释放，但我们仍需记录它曾经的映射关系，以便将来访问时能够将数据重新加载回内存。
##### 页表项的状态变化
- 页表项中的 V（Valid）位 = 0，表示当前 PTE 无效，CPU 不会从中解析出有效的物理地址。
  
### 双页表与单页表

#### 在单页表情况下更换页表
在内核态下修改 satp 寄存器的值。然后通过 sfence.vma 刷新 TLB。

#### 单页表情况下控制用户态无法访问内核页面
在 单页表 模式下，用户态无法访问内核页面，主要依赖于页表项（PTE）中的 U 位（User/Supervisor 位） 来控制访问权限。
- ```U = 1```：该页在用户态可以访问。
- ```U = 0```：该页仅能在内核态访问，用户态访问会触发异常（如 page fault）。
  
#### 单页表优势
Trap 的时候无需切换地址空间，而在任务切换的时候才需要切换地址空间。降低了实现的复杂度。而且在应用高频进行系统调用的时候能够避免地址空间切换的开销。

#### 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？
##### 双页表更换的时机
- 在 Trap 时，由用户态进入内核态，再由内核态返回用户态时都需要更换页表
- 任务切换时,如果新的任务属于不同的用户进程，自然要 换成它的用户页表（即新的 satp）。
  
#### 单页表更换的时机
- 系统调用、Trap 过程不需要换页表，页表中已经包含内核映射。
- 只有当从一个用户进程切换到另一个进程时才更换页表（通过切换 satp）。
